# 서버 비용과 배너 수익 시나리오 계산 절차

이 문서의 모든 금액·노출 수·사용자 수는 **가상 예시**다. 실제 청구액, 현재 인프라 비용,
광고 실적, 계정 정보, 리소스 식별자는 포함하지 않는다. 금융 원본과 실제 분석 보고서는
로컬 비공개 보관소에서만 다룬다. 공개 소스에 대한 승인으로 금융 데이터 공개를 허용하지 않는다.

## 비용을 구분하는 순서

1. 분석 기간의 시작 포함·종료 제외 날짜, 시간대와 `Estimated` 상태를 기록한다.
2. 계정 전체 청구 자료에서 `RecordType`별 `Usage`, `Credit`, `Tax`, 그 밖의 수수료·환불·
   약정 관련 항목을 분리한다. 계정 전체 합계를 앱 비용으로 부르지 않는다.
3. 리소스 태그와 비용 배분 태그 활성 상태를 확인한다. 비용 태그가 없거나 비활성인 경우
   태그 기반 앱 실제 청구액은 미확정이다. 조회 결과가 없다는 것을 비용이 없다는 뜻으로 해석하지 않는다.
4. 앱 전용 리소스와 연결 관계를 확인하고, 공유 네트워크·다른 앱의 서비스는 배분 근거 없이 포함하지 않는다.
5. 앱 전용 리소스의 현재 수량에 같은 리전의 공식 단가를 곱해 **크레딧 전 실행 비용 추정치**를 만든다.
   과거 실사용 비용과 현재 구성을 한 달 내내 유지한 추정치를 구분한다.
6. 컴퓨팅·DB·저장소·로드밸런서·공인 IP·시크릿의 고정 비용에 로그·백업·전송·요청 등
   변동 비용 여유분을 따로 더한다. 세금, 다른 공급자 비용, 인건비 포함 여부를 명시한다.
7. 크레딧 잔액·만료일이 확인되지 않으면 `unknown`으로 남긴다. 상쇄된 청구액으로 장기 수익 목표를 낮추지 않는다.

공식 근거: [AWS 비용 조회 API](https://docs.aws.amazon.com/aws-cost-management/latest/APIReference/API_GetCostAndUsage.html),
[비용 태그 활성화](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/activating-tags.html),
[AWS 가격 조회](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/price-changes.html).

## 배너 손익분기 수식

```text
배너 수익(USD) = 실제 표시된 유효 노출 수 / 1,000 × eCPM(USD)
손익분기 노출 수 = 올림(대상 비용(USD) / eCPM(USD) × 1,000)
필요 광고 대상 DAU = 올림(손익분기 노출 수 / 분석 일수 / 1인당 하루 유효 노출 수)
```

eCPM은 천 회 노출당 수익을 나타낸다.
[Google AdMob의 정의](https://support.google.com/admob/answer/15337570?hl=en).
앱 방문, API 요청, 광고 요청은 표시된 광고 노출과 같지 않다.
광고 제거 구매자·광고 동의 불가 사용자·미충전 요청은 수익 노출 수에 포함하지 않는다.
표시 노출을 기준으로 수익을 계산했다면 fill rate를 다시 곱해 이중 차감하지 않는다.

아래 **가상 월 비용 $80**과 **가상 USD eCPM $1·$2·$5**는 방법을 설명하기 위한 값이다.
실제 비용이나 실제 광고 단가로 해석하지 않는다.

| 가상 월 비용 | 가상 eCPM $1 | 가상 eCPM $2 | 가상 eCPM $5 |
| --- | ---: | ---: | ---: |
| $60 | 60,000회 | 30,000회 | 12,000회 |
| $80 | 80,000회 | 40,000회 | 16,000회 |
| $120 | 120,000회 | 60,000회 | 24,000회 |

가상 31일 기간, 가상 비용 $80, 가상 eCPM $2, 하루 5회 유효 노출을 가정하면
광고 대상 DAU는 `ceil(40,000 / 31 / 5) = 259`명이다. 이 수는 실제 사용자 수나 성과 전망이 아니다.
가상 match rate 80%, show rate 90%라면 40,000회 표시를 만들기 위한 광고 요청은
`ceil(40,000 / 0.8 / 0.9) = 55,556`회다. 이 비율 역시 실측값이 아니다.

## 일회 구매와 함께 계산할 때

```text
부족한 비용 = max(0, 대상 비용 - 배너 수익)
필요 신규 구매 수 = 올림(부족한 비용 / 신규 구매 1건의 순수입)
```

가상 비용 $80, 가상 배너 30,000회, 가상 eCPM $2이면 배너 수익은 $60이다.
가상 순수입 $3인 신규 일회 구매 7건이면 부족한 $20을 채운다.
이 순수입은 실제 상품 가격·수수료·환율을 적용한 결과가 아니다.
과거 일회 구매를 다음 달 수익에 반복해서 넣지 않으며, 광고 제거로 줄어드는 향후 노출도 반영한다.

## 실제 데이터로 바꿀 때 필요한 항목

같은 기간과 통화의 앱별·배너별 표시 노출, eCPM, 예상/확정 수익, 국가 비중,
match/show rate, 실제 광고 대상 DAU/MAU, 광고 제거 비중과 결제 순수입이 필요하다.
테스트 광고와 웹 방문 수를 운영 배너 수익으로 계산하지 않는다.
이 항목이 미확인인 동안 수익 보장이나 출시 후 매출 예측을 제시하지 않는다.

## 비용 절감안을 검토하는 기준

각 안에 공식 단가로 계산한 조건부 절감액, 소유자, 성능·가용성 영향과 검증 조건을 적는다.
태그 검토·트래픽 경로 검토·이미지 호환성 검토는 읽기 전용으로 수행할 수 있다.
현재 비용이 없는 자원을 제거해 생기는 절감액을 만들어 내지 않는다.
데이터·복구본 삭제, 운영 중단, 용량 축소, 네트워크 변경과 약정 구매는 이 보고 절차에 포함하지 않는다.

계산 재현: `python3 docs/monetization/banner_scenario.py --cost 80 --ecpm 1 2 5 --days 31`.
이 계산기는 입력값만 사용하고 금융 파일이나 클라우드에 접근하지 않는다.
